## Что теперь за игра

RoboCode - учебная игра-лабиринт на Python. Игрок пишет программу, робот идёт по клеткам,
собирает монеты и ключи и выходит в дверь. Всё, как в эталоне предметной области:
пользователь, уровень-лабиринт, попытка, результат, база знаний, словарь команд,
статистика игрока, таблица лидеров.

По ТЗ на уровне есть робот, монеты и ключ: по умолчанию 3 монеты, число может
отличаться по уровням. Монеты - коллекционные предметы, на балл они не влияют;
собирать их все для успеха не обязательно. Дверь открывает только ключ.

Из игры убрано всё боевое: боссы, враги, HP, ракеты, опасные клетки,
биомы, лёд/грязь (терраин), лимиты на число прогонов. Движок - плоская 2D-доска:
симулятор `Server_RoboCode/Server_RoboCode/Core/Game/LevelSimulator.cs` +
свой интерпретатор Python-подмножества (Lexer/Parser/Interpreter).
Робот умеет `robot.move()`, `robot.turn_left()`, `robot.turn_right()`;
языковые конструкции `for`, `def`, `print` - это Python, не команды робота.

## Как считается балл

Формула одна, константы названы в `GameRunService.cs`:

```
score = max(0, BASE - K_TICKS * ticks - K_LINES * linesCount)
BASE    = 100 * шкала сложности (лёгкий=1, средний=2, сложный=3, эксперт=4)
K_TICKS = 2
K_LINES = 5
```

- `ticks` - один вызов команды робота = ровно один тик.
- `linesCount` - `Lexer.CountCodeLines`: только строки кода, пустые строки и
  комментарии не считаются.
- Балл начисляется только за успех. Не прошёл - 0.
- Монеты на балл не влияют: в формуле только сложность, тики и строки.
  Собрать все монеты не обязательно, дверь открывает ключ.
- Если лучший результат уровня улучшился, суммарный балл в `player_statistics`
  пересчитывается автоматически (строго больше - иначе не перезаписываем).

## Шесть ограничений эталона (все в коде)

1. Врезался в стену - попытка не засчитывается (статус `error`, балл 0, кадр `crashed`).
2. Балл начисляется только при успешном прохождении.
3. `linesCount` считается по строкам кода без пустых строк и комментариев.
4. Вызов команды робота, которая не открыта, - попытка с ошибкой.
   Гейт строгий именно для `robot.*`; `for/def/print/len/range` и прочий Python
   не гейтятся - это язык, а не команды робота (проектное решение, комментарий
   в шапке `Interpreter.cs`).
5. Одна команда робота = один тик. Бонусов и штрафов за тип клетки больше нет.
6. Улучшение лучшего результата автоматически пересчитывает суммарный балл игрока.

## Шесть выходных документов эталона и их маршруты

| Документ | Маршрут |
|----------|---------|
| Отчёт о прогрессе игрока | `GET /api/profile` |
| Таблица лидеров (рейтинг игроков) | `GET /api/leaderboard` |
| Справка о прохождении уровня | `GET /api/levels/{id}/certificate` |
| История попыток игрока | `GET /api/attempts?levelId=&page=` |
| База знаний по доступным командам | `GET /api/knowledge-base` |
| Отчёт об активности игроков по уровням (админу) | `GET /api/admin/levels/activity` |

Плюс основной сценарий игры: `POST /api/execution/run` - запрос
`{ levelId, code, preview? }`, ответ `{ attemptId, status, success, ticks,
linesCount, keysCollected, keysTotal, coinsCollected, coinsTotal, score,
difficulty, errorMessage, errorLine, finalRobot: { cell, direction },
frames: [{ tick, robot: { cell, direction }, codeLine, keyTaken, coinTaken,
atExit, crashed }], console: [{ line, text, kind }] }`.
Справка по уровню без результата отдаёт 200 и понятную пустоту, а не 500.
История попыток всегда с пагинацией. Игроку видны только уровни со статусом
«доступен», статусы на сервере авторитетны: никаких разблокировок по звёздам.

## Приёмка двумя тестировщиками

Визуальный тестировщик (headless Chrome, вьюпорт 530x665, скриншоты в
`.qa_visual/`) прошёл 8 уровней (1, 2, 5, 6, 12, 17, 23, 24) и все страницы.
Интеграционный тестировщик прогнал I1-I13: контракт API, метрики и балл на
разных конструкциях, авария в стену, гейт команд, реплей против симулятора,
лучший результат и статистика, шесть документов, отчёт админа, статусы
уровней, регистрация/блокировка, сборки.

Найдено и исправлено 5 дефектов:

1. Стены на доске рисовались дважды: одно ребро из `map_data.walls` выводилось
   с двух сторон клетки, полоса была 6px вместо 4px (L5: 64 элемента на 32 стены).
   Теперь каждое ребро рисуется один раз (только `top` и `left` у клетки).
2. Страница уровня не влезала в экран: клетка задавалась жёстко от 520px,
   `.board-shell` выходил за вьюпорт (L1: документ 606px при экране 515px).
   Доска теперь тянется по ширине контейнера (`minmax(0, 1fr)`, `aspect-ratio`),
   клеток меньше 20px не бывает.
3. Профиль, рейтинг, база знаний, справка, история и админка обрезались на
   узком экране из-за фиксированного сайдбара 280px и отступов 40/48px.
   До 900px сайдбар стал рейкой 72px, отступы 16px, карточки переносятся.
   На всех 10 страницах `scrollWidth == clientWidth`, ни один элемент не вылезает.
4. Кнопка ▶ в конце реплея оставалась активной, но ничего не делала.
5. Даты показывались в UTC как локальные (справка 11:49 при местном 16:55).
   Фронт теперь дописывает `Z` к времени без смещения.

Плюс исправлен серверный дефект: `preview: true` от обычного игрока всё равно
сохранял попытку, результат и открывал ему команды (`GameRunService.cs`).
Теперь preview не пишет ничего независимо от роли, `attemptId: null`.

## Логика: приёмка этого раунда

Проверяли движение, повороты, выполнение команд, сбор ключей и монет, аварию
в стену, гейт команд, preview и реплей. Найдено и исправлено 4 дефекта:

1. `errorLine` в ответе `POST /execution/run` был всегда null: гейт команды,
   синтаксис, runtime-ошибка и авария не несли номер строки. Теперь
   `LevelSimulator.Finish` сохраняет строку, `BuildResult` её отдаёт.
2. Однострочный блок `for i in range(6): robot.move()` не разбирался, хотя
   подсказка уровня 3 использует именно такую запись. `Parser.ParseBlock`
   принимает тело в той же строке после `:`.
3. Runtime-ошибка (`print(zzz)`) не попадала в `console` с `kind: "error"`.
   Теперь `Interpreter.Fail` пишет ровно одну запись перед завершением.
4. Дверь на доске открывалась и статус писал «дверь: открыта», когда робот
   стоял на выходе без ключа. Дверь и статус теперь зависят только от ключа,
   `atExit` из условия убран.

Живая перепроверка после исправлений:

- errorLine: гейт `robot.turn_left()` на L1 - 1, синтаксис `robot.move(` - 1,
  runtime `print(zzz)` - 2, авария 7-м ходом - 7, успешный прогон - null;
- однострочный `for` на L1: тики 6, строки 1, балл 83; многострочный -
  тики 6, строки 2, балл 78; однострочные `if`, `def`, `while` тоже работают;
- консоль: runtime - ровно одна запись `error`, синтаксис - одна, успех - ноль,
  `print("привет")` на месте;
- L1-L7: все успешны, ключ 1/1, на L1 монеты 3/3 и кадр `coinTaken`,
  `turn_left` даёт `up`, `turn_right` даёт `down`;
- L3 без ключа: робот доходит до выхода, но `success: false`, сообщение
  «Дверь заперта: соберите все ключи (0 из 1)», на доске дверь без `is-open`,
  статус «дверь: заперта (нужен ключ)»;
- реплей: пауза, шаг назад/вперёд, скорость, в конце ▶ неактивна, счётчики
  ключей и монет совпадают с кадрами;
- preview от игрока: `attemptId: null`, попытки и результаты не пишутся;
- тестовые аккаунты удалены в порядке FK, счётчики БД снова 55/88/10/17/55.

Остаточные риски по логике:

- в плоском ответе `run` нет top-level `crashed`: авария видна по `status:
  "error"` и `frames[].crashed`;
- на всех 24 уровнях по одному ключу, поэтому ветка «собрано 1 из 2»
  проверена только чтением кода;
- после конца реплея подпись панели «Поле» остаётся «выполняется строка N»,
  а балл в середине реплея уже финальный - косметика, не блокирует.
